# ۱۵) معیارهای ارزیابی موفقیت سیستم

موفقیت در چهار سطح مستقل سنجیده می‌شود. **سیستم می‌تواند از نظر مهندسی عالی و از نظر پیش‌بینی بی‌ارزش باشد** — پس هر سطح جدا اندازه‌گیری می‌شود.

---

## سطح ۱ — کیفیت داده (پایه همه چیز)

| معیار | هدف | نحوه سنجش |
|---|---|---|
| **Data Completeness** | ≥ ۹۹٪ کندل‌های مورد انتظار موجود | مقایسه تعداد واقعی با تقویم بازار |
| **Data Freshness** | ≥ ۹۵٪ زمان، تأخیر < ۲× طول timeframe | `now − max(ts)` |
| **Validation Pass Rate** | ≥ ۹۹.۵٪ | نسبت رکوردهای رد شده |
| **Source Uptime** | ≥ ۹۸٪ در ساعات فعال بازار | `data_source_health` |
| **Gap Recovery Time** | ≥ ۹۰٪ گپ‌ها ظرف ۲۴ ساعت ترمیم شوند | `job_runs` |
| **Cross-Source Agreement** | انحراف قیمت < ۰.۵٪ | مقایسه دوره‌ای |

> اگر سطح ۱ پاس نشود، اعداد سطوح بعدی بی‌معنا هستند.

## سطح ۳ — کیفیت تحلیلی و پیش‌بینی ★ مهم‌ترین سطح

### ۳.۱ کالیبراسیون (مهم‌تر از Accuracy)
| معیار | هدف | چرا |
|---|---|---|
| **Brier Score** | بهتر از baseline نرخ پایه | خطای احتمال |
| **Calibration Error (ECE)** | < ۰.۰۸ | وقتی سیستم می‌گوید ۷۰٪، باید حدود ۷۰٪ درست باشد |
| **Reliability Diagram** | نزدیک قطر | نمایش بصری در داشبورد |

> یک سیستم با Accuracy ۵۵٪ و کالیبراسیون خوب، **بسیار ارزشمندتر** از سیستمی با Accuracy ۶۵٪ و کالیبراسیون فاجعه‌بار است.

### ۳.۲ قدرت پیش‌بینی
| معیار | هدف واقع‌بینانه | یادداشت |
|---|---|---|
| Directional Accuracy (افق ۲۴ ساعته) | ۵۳–۵۷٪ | هر ادعای >۶۰٪ پایدار = نشانه نشت داده |
| Precision در سیگنال‌های با Confidence بالا | ≥ ۶۰٪ | باید **به‌مراتب** بالاتر از سیگنال‌های Confidence پایین باشد |
| F1 | بهتر از baseline | |
| ROC-AUC | ≥ ۰.۵۵ | |
| **Monotonicity امتیاز** ★ | اکید | **کلیدی‌ترین آزمون**: دارایی‌های دهک ۱۰ امتیاز باید بازده میانگین بهتری از دهک ۱ داشته باشند |
| Information Coefficient (Spearman بین score و بازده آتی) | ≥ ۰.۰۳ | در امور مالی، IC = 0.05 خیلی خوب است |

## معیارهای «شکست» — کی باید متوقف شویم و بازنگری کنیم؟

این‌ها **Stop Conditions** صریح هستند:

| شرط | اقدام |
|---|---|
| Directional Accuracy پایدار ≤ ۵۰٪ روی OOS | استراتژی/فیچرها بازنگری شوند؛ **افزودن ویژگی جدید ممنوع** |
| Monotonicity امتیاز برقرار نیست | Scoring Engine بی‌ارزش است → بازطراحی وزن‌ها و نرمال‌سازی |
| Paper به‌طور فاحش بدتر از Backtest | توقف کامل توسعه ویژگی؛ شکار نشت داده |
| Data Completeness < ۹۵٪ | توقف تحلیل تا رفع منبع |
| IC ≈ ۰ پس از ۶ ماه | پذیرش صادقانه: سیستم ابزار **پایش و غربالگری** است، نه پیش‌بینی — و UI باید همین را بگوید |

> پذیرش این آخری از نظر مهندسی یک **موفقیت** است، نه شکست: یک ابزار صادق برای غربالگری و توضیح وضعیت بازار،
> بسیار ارزشمندتر از یک پیش‌بینی‌کننده دروغین است (بند ۳۲).
